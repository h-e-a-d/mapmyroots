# Repair the e2e suite (2026-10-30)

Goal: `npm run test:e2e` passes on a clean checkout, and CI's "E2E tests" job finishes and means something. Today CI cancels it on every run, so nothing it covers is protected.

## Baseline

Desktop Chrome against a local build of `main` (1a7c17b): 16 pass, 12 fail. The earlier note blamed "unstable" modal elements. That was wrong. The "not stable" lines are just Playwright retrying; the real blocker is the next line in each log.

## Causes

| # | Failing tests | Cause | Kind |
|---|---|---|---|
| 1 | avatar-cropper ×3, person-modal-rich-fields ×5 (8 total) | The tests call `page.locator('#genderMale').check()`. In `modal.css` the radio and its label have `pointer-events: none`, so the card (`.gender-radio-option`) is what receives the click, and `modal.js` handles it there. Playwright refuses to click an element the card covers. A real click on the card works (verified in a browser). | Test bug |
| 2 | person-modal-rich-fields "marriages section is visible" | **App bug.** `clearForm()` in `src/ui/modals/modal.js` empties `#personMarriagesMount` and sets `marriagesListHandle = null`. The marriages list is only mounted when editing an existing person (`populateFormFields`). So "Add person" shows a "Marriages" label with nothing under it, and there is no way to pick a spouse while adding. The design spec (`2026-05-07-rich-person-fields-design.md`) says the list shows one row plus "+ add another marriage". | App bug |
| 3 | tree-chart "adding a person renders a node", "Escape clears the highlight" | The test helper emits `tree:person:added` through `window.appContext`, which doesn't exist (the app deliberately has no such global, per CLAUDE.md). The emit is skipped, so the view never rebuilds. | Test bug |
| 4 | import-gedcom "imports 3 persons" | The import works. The test reads `#personCount`, which is in the collapsed cache indicator and is only refreshed on init and when the indicator is expanded. | Test bug |
| 5 | CI job | `.github/workflows/ci.yml` installs Chromium only but the config runs 6 projects (Firefox, WebKit, mobile Safari, iPad), with 1 worker and 2 retries inside a 15-minute limit. They can't launch, and the run gets cancelled. | CI config |

## Plan (one commit each, branch `fix/e2e-suite`)

1. **Shared helpers** in `testing/tests/helpers.js`:
   - `openAddPersonModal(page)`
   - `selectGender(page, 'male'|'female')`, which clicks the card like a user does
   - `addPersonViaUi(page, { name, surname, gender })`, which fills the modal and saves

   Then switch the 8 gender tests (cause 1) to the helpers.
2. **Marriages in add mode** (cause 2, app change). Mount `createMarriagesList` with no marriages in `clearForm()`, so the add modal shows one empty row. That is what the spec says, and the test already describes it. Check the save path and the `hasInvalidDate` guard with the list mounted for a new person, and add a unit-level check if the logic can be isolated.
3. **Tree-chart tests** (cause 3): add people through the real modal with `addPersonViaUi`, not by poking `treeCore`. That also covers the add flow end to end.
4. **GEDCOM test** (cause 4): assert the person count from `window.treeCore.renderer.nodes.size` and that the empty-state overlay is hidden, not the collapsed indicator's text.
5. **CI** (cause 5): run only `--project="Desktop Chrome"` in the e2e job and drop the 2 retries to 1. Keep the other projects in the config for local use. Add `Mobile Chrome` later only if it passes.
6. **Docs:** CLAUDE.md/ARCHITECTURE testing notes (how to run e2e locally, where helpers live), CHANGELOG line.
7. **Verify:** `npm run test:e2e` locally 3 times in a row on Desktop Chrome, all green, no flaky retries. Then `npm test`, `npm run check`, `npm run build`. Open the PR and confirm the CI e2e job finishes and passes before merging.

## Out of scope

- Firefox/WebKit/mobile projects in CI.
- The Astro upgrade and cookie consent.
- New e2e coverage beyond what exists, except the add-person flow that the tree-chart tests now exercise.

## Open question

Step 2 changes app behavior, not just tests. The alternative is to rewrite the test to expect an empty marriages area in add mode, but that would make the missing spouse picker the intended behavior and contradict the spec. I recommend fixing the app.

## Outcome (executed 2026-10-30 on `fix/e2e-suite`)

- Local Desktop Chrome: 29/29 pass, three runs in a row, plus one run with `CI=1` (1 worker, 1 retry, 1.2 min). Before: 16 pass, 12 fail.
- Cause 2 fixed in `modal.js` (`mountMarriagesList`, called from the add path).
- Found while fixing the tree-chart test: `builder-page.ts` wired the sidebar, view buttons and tree chart after a fixed 1000 ms, so the first test's click on the view button was silently dropped. It now waits for `window.treeCore` (up to 5 s) and sets `body[data-builder-ready]`; `openBuilder` waits for that flag.
- The tests that read `#personCount` now read `window.treeCore.renderer.nodes.size`, and the canvas-node tests use `openEditModalFor`.
- CI: Desktop Chrome only, readiness wait is a `curl` loop (no new dependency).
